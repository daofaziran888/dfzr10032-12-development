# 多源数据采集与RPA自动化平台

面向网页抓取、API接入、增量采集、RPA流程编排、数据校验与采集监控的数据工程平台。

这是一个前后端分离的管理平台：前端 Vue 3 + Vite + TypeScript，后端 FastAPI（Python）。
两边各自独立启动，前端 dev server 已关掉自动打开页面，启动后按终端打印的地址手工打开。

## 目录结构

```text
.
├── frontend/                 Vue 3 + Vite + TypeScript 前端
│   ├── src/views/            每个业务模块一个页面
│   ├── src/api/              统一请求封装
│   ├── src/stores/           会话与筛选状态
│   └── vite.config.ts        dev server 配置（open: false）
├── backend/                  FastAPI（Python） 后端
│   ├── app/routers/          每个业务模块一组接口
│   ├── app/services/         业务规则与状态流转
│   └── app/store.py          内存数据仓库与示例数据
├── .gitignore
└── docker-compose.yml
```

## 启动

### 后端

```bash
cd backend
python3 -m venv .venv && .venv/bin/pip install -r requirements.txt
./run.sh
```

健康检查：`curl http://127.0.0.1:8000/api/health`

### 前端

```bash
cd frontend
npm install
npm run dev
```

前端默认监听 `http://127.0.0.1:5173/`，dev server 不会自动打开浏览器，
需要自己访问。`/api` 由 vite 代理到后端 `http://127.0.0.1:8000`。

## 采集调度批次

调度计划只描述“什么时候跑哪个任务、依赖谁”，真正驱动流转管道的是批次清单
（`/schedule_batch`，接口 `/api/schedule_batch`）：

- **按时段派发**：`POST /api/schedule_batch`，传 `调度时段`（如 `2026-11-20 08:00`）
  派发该时段到点的全部计划，或再传 `计划编号` 只派发单个计划。
  日周期只在自己设定的时刻触发，小时周期按整点触发，周周期按同星期几触发。
- **同一时段只派发一次**：同一任务在同一时段键（日=日期 / 小时=日期+小时 / 周=ISO 周）
  只有一条批次，重复派发返回已有批次并提示“未重复派发”。
- **等待与确认分开记录**：批次上同时有 `等待依赖`、`已确认依赖` 两份快照，
  `依赖状态` 取 `同时段等待 / 接续等待 / 已确认 / 依赖缺失 / 无依赖`。
- **后继只消费已确认结果**：依赖未确认时 `开始执行` / `确认结果` 都会被拦下，
  前置批次 `确认结果` 后自动解除等待并把后继转入 `待执行`。
- **周期切换接续**：6 点的日周期库存采集还在取数时，8 点切小时周期的汇总批次
  接续这条已发出的前置批次（`接续批次` 字段），不重新派发执行任务，
  并根据前置批次预计完成时间推算下一批数据的 `预计可用时间` 与 `可用延迟分钟`。
- **流转执行节点**：`POST /api/flow_node` 用 `批次编号`（或 `调度时段`）生成可执行节点，
  节点带 `前置批次` 和 `依赖结果`（含确认数据、结果标识、来源关系）；
  依赖未确认的批次被阻断，同一批次在同一管道下只生成一个节点。

批次动作：`开始执行`、`确认结果`（可带 `确认数据`、`结果标识`）、`挂起批次`、
`恢复批次`、`重试依赖`。

回归测试（需额外安装 `pytest`）：

```bash
cd backend && python3 -m pytest tests -q
```

## 约定

- 每个模块的前端页面在 `frontend/src/views/<模块>/index.vue`，后端接口在
  `backend/app/routers/<模块>.py`，业务规则在 `backend/app/services/<模块>.py`。
- 列表接口统一返回 `{ items, total, page, size }`，动作接口统一返回 `{ ok, message }`。
- 状态流转只允许在 `app/services` 里改，路由层不做业务判断。
